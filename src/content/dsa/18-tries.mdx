## The one question this page answers

A dictionary is easy to search: build a hash set and ask "is this word present?" in O(1). Harder
question, asked by autocomplete, spellcheck, and Word Search II: _is this PREFIX still alive, and
which words share it?_ Hash sets answer strings, never prefixes. The trie's question is sharper:
_can a tree where each node is one character make prefix answers as cheap as whole-word answers?_
Yes — both cost O(L).

## Start with an analogy

A phone keypad with letters spelled out by walking. To enter "cat" you press C, then A, then T —
each press moves you one level deeper. The keys form a branching tree: press A at the top and every
word beginning with A hangs from that branch; words like "cat" and "care" march side by side down
the shared "ca" stairs before diverging.

The trie is that keypad made of nodes: each node is one letter, each child is "the letter that can
come next", and a stored word is any node marked "this is a valid final destination".

## The node is two facts

A trie node holds only:

- **children** — the letters that have been seen next after this one; a map from character to node
  is the typical in-memory choice.
- **word-end flag** — a single boolean: a complete stored word ends right here.

The node does not store the whole prefix because the path to it already spells it. That is the
memory trick — the position in the tree IS the string.

## Insert: walk, create, mark

To insert a word, walk from the root, following the child named by each letter:

- child exists → descend into it,
- child missing → create it, then descend.

After the last letter, set the word-end flag on the node reached. The shared prefix effect: "cat"
and "care" build the root → c → a spine once. Only the differing final letters branch.

## Search vs startsWith — the one-flag difference

- `search(word)`: walk the letters; if any child is missing, return false; at the end, return the
  WORD-END flag of the node. "car" in a trie holding only "care" has a node — but no end mark — so
  search says false.
- `startsWith(prefix)`: walk the same way and return true if the path survives to the end — the flag
  is irrelevant. Every stored word makes all of its prefixes pass.

That one flag is the entire difference, and it is the trie's signature trick.

## Word Search II: the trie in the wild

Searching a board for many words at once is backtracking plus the trie:

1. Insert all words into one trie once.
2. From every board cell, DFS the neighbors, descending through the trie.
3. The moment a letter has no child in the trie, the branch dies — no word can continue this way.
4. When a DFS lands on a word-end node, record the word and unmark the flag so the same word is
   never reported again, even if a second path can also spell it.

Without a trie, "does any of these words start here?" is a scan of the word list at every cell. With
it, the check is one child look-up — the tree collapses the whole vocabulary.

## What this is NOT

| Misconception                                    | Truth                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| "A trie is a sorted list of words"               | It is a tree of single characters built from shared prefixes; no actual word exists as a unit.     |
| "search and startsWith give the same answer"     | Same walk, different final test — the word-end flag separates a complete word from a live prefix.  |
| "A trie is faster than a hash set at everything" | For exact-word look-ups they are comparable; the trie wins at PREFIX questions and pays in memory. |
| "Insert needs to create a node per letter"       | Only for letters the walk finds missing; shared prefix nodes are reused and just passed through.   |
| "Word Search II is about fast lookups"           | It is about pruning: the trie kills every board prefix that matches no stored word, step by step.  |

## Why this matters for the rest of the trip

The trie pairs the tree intuition of the binary-tree days with the "string as a path" idea that
recursion already rewarded. It is the backbone of autocomplete and spellcheck, and the pruning
discipline here — stop the moment the path stops promising — is exactly the backtracking discipline
you sharpened in the backtracking day, now wearing a prefix tree. Master "walk the path, mind the
end flag" and prefix problems stop being exotic.

Solve the two problems above: the first turns the trie vocabulary into method calls; the second
makes the trie prune a board search one letter at a time.
