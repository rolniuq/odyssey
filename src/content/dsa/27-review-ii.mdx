## The one question this page answers

Two tools, one shared spine. Trees and dynamic programming are both recursion over smaller
structures: a subtree is a smaller tree, a prefix is a smaller string. This page asks one question:
_can you recall both against harder inputs?_ Lowest Common Ancestor needs a post-order walk — the
answer appears on the way back up. Word Break needs a table — the answer builds left to right. Same
recursive instinct, two different directions of resolution.

## Start with an analogy

A family-reunion puzzle. Two cousins want the nearest ancestor they share. You stand at the root of
the family tree and shout down: every branch reports back who it found. At a node, if the left
branch found one cousin and the right branch found the other, this node is the meeting point — the
answer is discovered not while descending, but on the way back up.

A freight-yard puzzle. A long train of cars reads `leetcode`, and you have a placard of valid block
names: `leet`, `code`. Can you break the train into valid blocks? You do not try every combination
blindly — you walk the train one car at a time and write, on a card, whether the train _up to this
car_ can be fully split. Each new card reads the earlier cards.

The shouting tree is LCA recursion. The row of cards is the Word Break table.

## Trees and DP: the same spine, different resolution

Both tools take a big problem and recurse on a strictly smaller one, but they resolve in opposite
directions:

- **Trees** recurse into _smaller structures that branch_. The base case is an empty node, and the
  merge step combines two child answers into a parent answer. LCA is the cleanest example: a node
  cannot know it is the answer until both children have reported.
- **DP** recurses into _smaller prefixes of the same structure_. The base is the empty prefix, and
  each cell combines earlier cells that are strictly smaller. Word Break is the cleanest example: a
  prefix is splittable exactly when an earlier splittable prefix is followed by a dictionary word.

Both are Day 7 recursion wearing different hats. Today's pressure: LCA must also _build_ its tree
from a flat array, and Word Break must not be fooled into greedy segmentation.

## Lowest Common Ancestor: decide on the way back up

The adapted input is a level-order array, `null` marking a missing child. First rebuild the nodes:
read values in level order, giving each node a left child then a right child from the queue. Then
the walk:

1. If the node is `null`, return `null`.
2. If the node's value is `p` or `q`, return the node — it is a target, and a target is its own
   ancestor.
3. Search both children. If **both** return a node, this node is the LCA. If **one** returns a node,
   pass it up. If neither does, return `null`.

The answer resolves exactly once: at the node where the two halves report a hit each. Watch the
visualizer walk the tree for `p=5, q=4` — the walk descends left, confirms 4 lives inside 5's
subtree, and returns 5. Cost: O(n) for one post-order pass; the rebuild is also O(n).

## Word Break: the table fills left to right

`dp[i]` = can the prefix `s[0..i)` be segmented. The base `dp[0]` is `true`. The transition: try
every cut `j` before `i`; if `dp[j]` is true and `s[j..i)` is a dictionary word, then `dp[i]` is
true. The final answer is `dp[s.length]`.

The table is what keeps the search honest. A greedy attempt — "grab the longest matching word" — is
one path through the search space and can dead-end. The table evaluates every cut at every position,
so a dead end in one branch never poisons another. Watch the visualizer fill `leetcode` with
`{"leet","code"}`: `dp[4]` lights up when `leet` follows the empty prefix, `dp[8]` when `code`
follows `dp[4]`. Cost: O(n²) with O(n) space, and each cell is built only from strictly smaller
ones.

## What this is NOT

| Misconception                                | Truth                                                                                                                                     |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| "LCA needs parent pointers"                  | The post-order recursion reports up from the children; no parent pointer exists, and one walk through the tree is enough.                 |
| "A node is never its own ancestor"           | By definition a node is an ancestor of itself, which is exactly why the answer can be p when q sits inside p's subtree.                   |
| "The LCA is the node with the smaller value" | Ancestry is about depth and structure, not value; the recursion finds the meeting point, never a numeric minimum.                         |
| "Word Break can be solved greedily"          | A locally-greedy first match can dead-end; the table explores every cut, so one blocked branch cannot poison the rest.                    |
| "DP and tree recursion are unrelated"        | Both recurse on strictly smaller structures; trees merge two branch answers, DP reuses smaller prefix answers — one instinct, two shapes. |

## Why this matters for the rest of the trip

decide" shape is every tree problem you will face — and the "answer a prefix from earlier prefixes"
shape is every 1D DP. Tomorrow's final sprint mixes the whole sequence — two pointers, windows,
trees, tables — into a single set of review problems, and the instinct you are recalling today is
what holds them all together.
