## The one question this page answers

You have a list and you must evaluate a statistic over _every contiguous slice_ — the best span to
own a stock, the longest stretch with unique letters. The lazy answer recomputes each slice from
scratch, and if a slice can be k long you pay **O(n·k)**. The sliding window asks: _can each step
rebuild the slice with just one element in and one element out?_ Yes — and then a careful double
pass costs **O(n)**.

## Start with an analogy

A conveyor belt of products rolls past a quality inspector. The inspector examines not one item but
a batch — the current k on the line. Sliding the tray one slot forward does not mean inspecting all
k items again: the tray just dropped the leftmost item and picked up the newest on the right. The
inspector updates the batch summary (weight, count, "still fresh?") with those two changes alone.

The array is the belt. The tray is the window. Its two edges are `left` and `right`, and the
_aggregate_ is the one number or condition the inspector carries between slots.

## One aggregate, two edges

Every sliding window is the same skeleton. `right` claims new ground; `left` retreats only when the
claimed ground breaks the constraint. The statistic is not recomputed — it is **updated**: subtract
what the left edge dropped, add what the right edge picked up. When the aggregate can be updated
this way, the whole pursuit collapses to a pair of pointers walking the array once.

### Fixed width: exactly k consecutive items

The maximum-of-any-k problem is the purest form: each step adds `nums[right]` and removes
`nums[left]`, so the batch total stays live in O(1). Nothing ever needs a second look.

### Variable width: shrink when the rule breaks

Longest Substring Without Repeating Characters is the flexible version. `right` extends the current
unique-letter run; the moment a character already inside the window reappears, the window is
invalid, and `left` jumps just past that earlier copy to make it valid again. The map of "last seen
index" is what lets the jump land in one move.

### The invalidation rule — the half the work

Different windows fail differently. Stock prices: the aggregate is "cheapest buy so far", and the
left candidate resets whenever a new low appears (any pair using the old low is dominated). Longest
unique substring: the aggregate is "has anything here repeated?", and the left jumps when an
incoming character collides with one already inside. Naming the invalidation rule first is what
makes the code write itself.

## The honest cost argument

Two edges, each only ever moving forward: **at most n moves each, 2n total, O(n)**. The pitfall is
updating the aggregate in O(1) — that is where the "shrink" bookkeeping has to be cheap, exactly
like the two-pointer discard from Day 2.

## What this is NOT

| Misconception                                     | Truth                                                                                                                    |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| "A sliding window is a loop that slides an index" | It is a pair of edges with an incremental aggregate; the trick is what changes as the edges move, not the loop.          |
| "It recomputes the slice every step"              | The whole point is O(1) updates: one element in, one element out. Recompute is the non-solution.                         |
| "It works on any sequenced data"                  | It needs the slice to be contiguous AND the aggregate incrementally updatable — a global pair (Day 1/2 shape) is not it. |
| "Only fixed widths count"                         | Variable-width must be even more careful about when to pull the left edge; both flavors are O(n).                        |

## Why this matters for the rest of the trip

Sliding window is two pointers with a moving edge (Day 2), plus an aggregate to babysit — keep that
line in your head and window problems stop being a new category. The pattern returns in _Minimum
Window Substring_, _Permutation in String_, and the frequency-counting variants, and its "grow the
right edge, shrink the left when a rule breaks" rhythm is the same one you will use when you meet
monotonic queues later.

Solve the two problems above before moving on — then try _Fruit Into Baskets_ and _Permutation in
String_ on LeetCode to feel both a two-pointer and a hashing flavor of the same skeleton.
