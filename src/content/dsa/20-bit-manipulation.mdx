## The one question this page answers

Given a pile of numbers, the honest way to find the one that does not fit — the value that appears
once, or the value that went missing — is to sort or to count. This page answers one question: _can
a single bitwise fold find the outlier without sorting and without a hash set?_ The answer is yes —
XOR. Because any value folded in twice cancels itself, a running XOR silently discards every
duplicate and keeps exactly the value you are hunting for. That is the whole trick, and it is one of
the few places a bitwise operator solves an entire interview problem on its own.

## Start with an analogy

A row of light switches, each either on (1) or off (0). A single bit is just such a switch. Now add
one rule: flip a switch twice and it returns to its starting state. That rule — a flip followed by
its twin cancels — is XOR. Fold the switches of each number into a tally one at a time: every number
that arrives twice flips its switches off again and vanishes, leaving only the switches that were
flipped an odd number of times. The lone survivor is the answer you want.

## Bits are tiny on/off flags

Every integer is a string of bits, and each bit is one switch. Three operators do the flag work:

- **AND (`&`) tests.** `n & 1` keeps only the lowest bit, answering parity: 1 for odd, 0 for even.
- **OR (`|`) sets.** `x | 1` forces the lowest bit on.
- **XOR (`^`) flips.** `x ^ 1` toggles the lowest bit.

Reading and flipping individual flags is the everyday half — masks, permissions, state bits. The
interview half is the XOR trick, and it needs only the three identities in the next section.

## XOR: the cancel button

Two identities do all the work:

- `x ^ 0 = x` — zero flips nothing, so a running tally may start at 0 and keep every value folded
  in.
- `x ^ x = 0` — a value meets its own copy and cancels completely.

Compose them: fold a number in twice and the second fold undoes the first, leaving the tally exactly
as it was. That is why pairs disappear. Watch it live in the visualizer: `[4, 1, 2, 1, 2]` folds to
4 — the two 1s and the two 2s cancel, and 4, the sole loner, survives.

## Two problems, one fold

**Missing Number** runs the fold twice over the range: start the tally at `n` — the largest value in
`0..n` — then for each index `i` fold in both `i` and `nums[i]`. Every present value is folded
twice, once as an index and once as a value, so it cancels. The missing value is folded only as its
index, so it survives. For `[3, 0, 1]` the fold from `n = 3` leaves 2.

**Single Number** is even simpler: fold the whole array into a tally starting at 0. Each duplicate
pair cancels; the value that appears once remains. For `[2, 2, 1]` the 2s vanish and 1 survives.
Both are one pass at O(1) memory — no sorting, no hash set.

## What this is NOT

| Misconception                         | Truth                                                                                                                |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| "XOR is a kind of addition"           | It is bitwise with no carries or borrows: bits differ → 1, bits same → 0. The identities, not arithmetic, drive it.  |
| "XOR is a kind of hashing"            | Hashing needs a table; the XOR fold keeps no memory at all — one integer, O(1) no matter the input size.             |
| "Bit tricks are micro-optimizations"  | The XOR fold is a genuinely different algorithm — one pass, no extra memory — not a speed tweak on a sorted loop.    |
| "The XOR trick can find any outlier"  | It only answers pairwise-cancellation shapes — the value folded an odd number of times. It cannot count occurrences. |
| "Single Number needs a set or a sort" | One XOR fold replaces both; duplicates cancel themselves without ever being compared.                                |

## Why this matters for the rest of the trip

The switch-flipping instinct — XOR cancels pairs — reappears wherever pairs are the enemy:
hash-based deduplication, sets, and the parity checks scattered through later problems. And the
deeper habit on display is one this whole track rewards: look for an operation that lets most of the
data cancel itself, so the exception stands out. Master the two identities and the two problems, and
bit manipulation stops being magic.

Solve the two problems above. Missing Number folds indices against values; Single Number folds the
array against itself — make sure you can say, for each, which value "should" have cancelled and why
it did not.
