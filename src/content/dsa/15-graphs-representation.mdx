## The one question this page answers

A graph is a baker's bill of relationships: who is connected to whom, and how. Before any algorithm
can run, the program must answer a boring-sounding question — _where do I put this shape in memory?_
There are two classic answers. This page shows both, teaches how to choose between them, and then
shows that a humble 2D grid is secretly a graph wearing a costume.

## Start with an analogy

Imagine a city you want to navigate. Two ways to store its road map:

- A **spreadsheet of every intersection pair**: rows and columns are all the intersections; each box
  says "road / no road." To know if Main and Pine connect, peek at one box. But the spreadsheet has
  a row and column for _every_ intersection, so a city of a million intersections needs a trillion
  cells even if only a few streets exist.
- A **driveway-by-driveway robber list**: for each intersection, a short list of the streets that
  leave it. This takes space proportional to real streets, and to plan a route you walk each
  intersection's list.

Both describe the same map. One answers "do these two connect?" instantly; the other is smaller and
easier to walk. Nobody is "correct" — the map only tells you which trade you are about to pay.

## Nodes, edges, V and E

A graph is a set of **nodes** (vertices) and a set of **edges** between them. `V` is the node count,
`E` the edge count. In an **undirected** graph an edge is two-way (roads); in a **directed** graph
edges are one-way arrows. Two vertices are **neighbors** when an edge connects them.

## The adjacency matrix

The matrix is the spreadsheet: a `V × V` grid, plus a rule — `M[i][j] = 1` exactly when an edge
joins `i` and `j`.

- **Edge look-up:** is `i` joined to `j`? One poke at `M[i][j]` — O(1).
- **Neighbor iteration:** walk row `i`, collect the `1`s — O(V) no matter how few neighbors exist.
- **Space:** O(V²), with the zeros stored beside the ones. Dense graphs pay it happily; sparse
  graphs waste it.

The visualizer builds the matrix for a four-node graph — watch the `1`s light up in read row `0`,
then see how the mirror-image `1`s betray that the graph is undirected.

## The adjacency list

The list is the index-card box: each node keeps an array of its neighbors.

- **Edge look-up:** in the worst case, scan a node's row — O(degree), which is O(V) worst case.
- **Neighbor iteration:** walk the row — O(degree), as cheap as it gets.
- **Space:** O(V + E). Sparse graphs cost only what they actually contain.

The visualizer ends with the same four-node graph as a list — count the cells and notice how much
smaller the sparse story is.

Picking between them is density: when the graph is sparse (most pairs lack an edge) the list wins;
when you constantly ask "does this exact edge exist?" — or V is small enough not to care — the
matrix wins. Both appear in interviews; both are expected vocabulary.

## Grids are graphs in disguise

A 2D grid has no stored edges, yet every gray cell has implicit edges to its four orthogonal
neighbors. So "reachability on a grid" is graph traversal without a graph structure:

- **Number of Islands** counts connected components of `'1'` cells: for each untouched land cell,
  count one island and expand through the four edges, erasing what you have visited.
- **Flood Fill** colors one connected region: from the seed pixel, spread through same-color
  neighbors and stop at the color's boundary — exactly reachability in a graph whose edges are
  same-color adjacency.

In both, the DFS/BFS machinery of tomorrow's traversal applies to a graph you never materialize.

## What this is NOT

| Misconception                        | Truth                                                                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| "An adjacency matrix IS a graph"     | It is one storage choice among two. The graph is nodes plus edges; the matrix is only a picture of it.                     |
| "Lists are always better"            | Dense graphs and hot edge-look-up questions make the matrix cheaper. Choose by density and workload, not by default.       |
| "Grids are not real graphs"          | Cell adjacency is an edge relation; grids are graphs with an implied structure, and traversal algorithms apply unchanged.  |
| "Storing the graph is the hard part" | Representation is the prelude. The questions that actually matter — reachability, shortest paths — come next and reuse it. |
