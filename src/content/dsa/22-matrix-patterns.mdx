## The one question this page answers

Matrices look like two-dimensional monsters, but every matrix problem is just a loop with two
indices — row and column — and the pain is deciding what each index does next. This page answers one
question: _can the scariest matrix walks be written as simple loops over cells you can name?_ Yes.
Rotating a square is the two-step recipe of transpose-then-reverse-rows, and a spiral is the
boundary-peeling loop the visualizer above runs. Both are tame once you name the coordinates and
keep the boundaries honest.

## Start with an analogy

A photo album. To rotate a square photo 90°, you do not pick it up and spin it; you mirror it across
its diagonal — the top-right corner lands where the bottom-right was — and then flip each row like a
page. Two whole-print moves, every pixel lands exactly once.

The album is a spiral-read journal: you read the cover edges clockwise — top strip left to right,
right strip down, bottom strip right to left, left strip up — then flip to the next inner page and
read its edges the same way, until one strip is left.

## Name your cells

A matrix is `matrix[row][column]`: the outer array picks a row, the inner array picks a column. All
matrix logic — rotations, spirals, transposes — is just choosing which index you fix and which you
vary, and how far each goes. Write the bounds explicitly (`top`, `bottom`, `left`, `right`, or `i`,
`j`) and the loop writes itself.

## Rotate Image: transpose, then reverse

To rotate an n × n matrix 90° clockwise in place, without a second grid:

1. **Transpose:** for every `i < j`, swap `matrix[i][j]` and `matrix[j][i]`. This mirrors the matrix
   across the main diagonal.
2. **Reverse each row.** The mirror-then-flip composition is exactly a clockwise quarter-turn.

Each cell is swapped once in the transpose and once in its row reverse — O(n²) time, O(1) extra
space, and no `temp` matrix.

## Spiral Matrix: four boundaries, four edges

The spiral is a loop that keeps shrinking the box you still have to read:

- `top = 0`, `bottom = m - 1`, `left = 0`, `right = n - 1`.
- Read the top edge `left → right`, then `top++`.
- Read the right edge `top → bottom`, then `right--`.
- **If** `top <= bottom`: read the bottom edge `right → left`, then `bottom--`.
- **If** `left <= right`: read the left edge `bottom → top`, then `left++`.
- Stop when `top > bottom` or `left > right`.

The two `if` guards are what keep skinny matrices — one row or one column — from double-reading; the
boundaries make a visited grid unnecessary.

## What this is NOT

| Misconception                                        | Truth                                                                                                                 |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| "Matrix code needs a helper grid"                    | Transpose and spiral both track indices only; a visited grid is extra memory the boundaries already make unnecessary. |
| "Rotate 90° means rotate each ring separately"       | Ring-by-ring rotation works but is needlessly fiddly; transpose-then-reverse-rows is simpler and equivalent.          |
| "Spiral order is arbitrary"                          | It is one deterministic path: top edge, right edge, bottom edge, left edge, tightening one boundary per pass.         |
| "The diagonal participates in every swap"            | In a transpose the diagonal cells (i === j) map to themselves and are skipped; only off-diagonal pairs swap.          |
| "In-place means the algorithm is automatically fast" | In-place just means O(1) extra space; the time is still O(n²) for rotation because every cell must move.              |

## Why this matters for the rest of the trip

Matrix problems are where index discipline gets tested: off-by-one errors in boundaries silently
drop or double cells, and the spiral's guards are the same boundary logic used in binary search and
two-pointers — know when a range is live and when it has crossed. The transpose recipe also powers
matrix power, image filters, and grid games. Learn to name every cell by (row, column), keep your
boundaries explicit, and the two-dimensional monsters turn into one-dimensional loops.

Solve the two problems above. Rotate Image is a two-recipe composition; Spiral Matrix is a single
loop with four shrinking counters. For each, write out the bounds before you write the loop — and
check the single-row and single-column shapes against your guards.
