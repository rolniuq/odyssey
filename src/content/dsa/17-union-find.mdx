## The one question this page answers

Connectivity questions — _are these two things already linked? how many separate groups exist?_ —
look begging for a traversal each time, which costs O(n) per question. The page's question: _can we
answer "same group?" in near-constant time, after a cheap setup?_ Union-Find says yes, with the
daring storage choice of giving every node exactly one parent pointer.

## Start with an analogy

A village fair. Each person holds a string; the string in your hand points at some other person. The
delegation of the whole crowd is: whoever you are, pull strings until you reach the one person whose
string loops back to themselves — the **root** of your group. Everyone sharing that root is one
neighborhood.

Two neighbors run into each other. To merge the neighborhoods they do not tie every pair of hands;
the two **roots** agree first, and one root hands its string to the other. Everyone in the smaller
group is now, with a pull of a few strings, part of the larger group.

The string holder is a **parent**; pulling strings is **find**; roots shaking hands is **union**.

## The parent array and find

The data is shockingly small — one integer per node:

- `parent[i]` = the parent of node `i`.
- A node is a **root** when `parent[i] === i`.
- `find(x)` walks `parent[x]`, `parent[parent[x]]`, … until it reaches a root.

Two nodes are in the same component exactly when `find(x) === find(y)`. To **union(x, y)**: find
both roots, and if they differ, point one root at the other — the two components become one.

## Path compression

During `find(x)`, the walk sees every ancestor on the way to the root — and at the end it owns the
answer for all of them. So `find` rewrites its own path: every node walked is repointed straight at
the root. Next time any of them is asked, it is one hop. This pays for itself so well that a bare
`find` with compression, done on a sequence of operations, is already almost linear.

## Union by size

Which root attaches to which matters. If the bigger root always stays the root and the smaller tree
is hung under it, every node's depth can only grow when its tree is the smaller one being absorbed —
and that can happen only O(log n) times per node. Shallow trees, short walks. Union by size and path
compression together give the famous near-constant **α(n)** — a function so slow it is
indistinguishable from 1 for every practical n.

## Counting components

Number of Provinces starts with `count = n` (every city is its own province) and scans the
`isConnected` matrix. Each `1` between cities `i` and `j` triggers `union(i, j)`; a _successful_
union — two different roots merged — decrements the counter. What survives is the number of roots,
which is the number of provinces, because every root names exactly one disconnected group.

## What this is NOT

| Misconception                              | Truth                                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| "Union-Find is a graph representation"     | It does not store edges at all — only a parent per node. It answers connectivity questions about a partition. |
| "find(x) just returns parent[x]"           | It returns the ROOT, walking any number of parents to find it.                                                |
| "union joins the two nodes directly"       | It joins the two components through their roots; same-root membership is a no-op that reveals a cycle.        |
| "Trees can grow tall and slow like a list" | Path compression and union by size keep them shallow; the amortized cost is near-constant.                    |
| "Union-Find replaced adjacency lists"      | They answer different questions — lists map who is adjacent; union-find maps who shares a group.              |

## Why this matters for the rest of the trip

Union-Find is the quiet workhorse behind connectivity — connected components, cycle detection in
undirected graphs, and Kruskal's minimum-spanning-tree all lean on "same root?" being nearly free.
Wherever a problem asks "are these already linked?" in a context that changes as edges arrive,
traversing each time is the crude answer; union-find is the disciplined one. Pair it with the
traversal instincts of the graph days and the overlap thinking of the interval days, and
connectivity problems stop looking scary.

Solve Number of Provinces above — then the connected-components instinct will show up again in the
union-find flavoring of future graph problems.
