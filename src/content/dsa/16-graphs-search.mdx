## The one question this page answers

A graph can be explored in a brute-force diagonal order: wander without a plan and you loop forever,
touch the same nodes twice, and still answer nothing. The page answers a single question — _in what
order do I look at the frontier?_ — and shows that two famous answers to it, a queue (BFS) and a
stack (DFS), share all their hygiene (mark visited, skip repeats) and differ only in which node each
turns to next.

## Start with an analogy

You are inside a building and must search it. Two policies:

- **Floor by floor.** Check every room on the ground floor, then the entire first floor, then the
  second. You may walk a lot in the early rounds, but you meet the fire exit in the fewest doors
  possible — and you always know you have seen everything within a certain walking distance.
- **One stairwell at a time.** Trust the first staircase, go as deep as you can, come all the way
  back, then try the next staircase. You find the hidden cash sooner, but you can sneak past the
  fire exit steps away.

The queue is the "floor by floor" schedule: rooms discovered first are explored first. The stack is
the "one stairwell at a time" schedule: the most recently discovered room is explored first. Neither
is wrong; the building just decides what you find and in what order.

## The shared spine of every graph search

Whatever the policy, both searches run the same loop:

1. Hold every discovered-but-unexplored node in a **frontier**.
2. Take one node off the frontier, and look at its **neighbors**.
3. Any neighbor never seen before: **mark it visited** and add it to the frontier.

The visited mark at _discovery_ — step 3 — is the hygiene that keeps the loop finite. If you marked
on arrival instead, a node with two frontiers parents would be queued twice. State the rule: _race
to the mark_.

### The queue: BFS

Use a **queue** (FIFO) as the frontier. Nodes discovered first are explored first, so the frontier
always contains an entire "wave" at one distance, then the next. Everyone at distance 1 is explored
before anyone at distance 2 — that layering is what makes BFS finds fewest-edge paths and what makes
it the natural tool for "closest / how quickly".

### The stack: DFS

Use a **stack** (LIFO), or recursion. The most recently discovered node is explored next, so the
search plunges down a single path until it bottoms out, then unwinds and tries the next branch. DFS
is the tool for "explore every possibility" and for cycle detection: a path that re-enters a node
still on the recursion stack has closed a loop, a **back edge**.

## Topological search: might be a special mark

Course Schedule's prerequisites form a directed graph. A **topological order** lists courses so
every course appears after its prerequisites — such an order exists exactly when the graph is
acyclic. Kahn's algorithm is BFS's twin for this:

1. Count every course's **indegree** (how many prerequisites still block it).
2. Queue every course with indegree 0 — nothing blocks it, so it is schedulable now.
3. Dequeue one, and decrement the indegrees of the courses that need it.
4. A course whose indegree falls to 0 joins the queue.

If the count of scheduled courses falls short of `numCourses`, a cycle keeps every remaining course
blocked forever, and the answer is `false`.

## Cloning: the visited set becomes a map

Clone Graph asks for a deep copy of a node graph. The twist: the copy must mirror the original's
_references_, not just its values. A `visited` boolean is a boolean; a **map from original node to
its clone** is a memory. When a neighbor points at a node already cloned, the map hands back the
existing clone — shared nodes and cycles in the original become shared nodes and cycles in the copy.
Recursion without that map on a cyclic graph never terminates; with it, each node is cloned exactly
once and the shape is preserved.

## What this is NOT

| Misconception                                | Truth                                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| "DFS and BFS are different algorithms"       | The only difference is the frontier policy — queue vs stack. The visited discipline is byte-for-byte shared. |
| "Visited marks are optional if I am careful" | Without them a node with two paths in gets queued twice and, on cyclic graphs, the search never ends.        |
| "BFS finds shortest paths in any graph"      | Only for fewest-_edges_ paths on unweighted graphs; with weighted edges the layering guarantee breaks.       |
| "DFS cannot detect cycles"                   | The recursion stack version detects them precisely — a back edge into the active path is a cycle.            |
| "Cloning just copies values"                 | It must preserve references through a map, or shared/cyclic structure breaks the clone.                      |

## Why this matters for the rest of the trip

Every graph problem you will meet — shortest paths, connected components, topological order, even
puzzle solving — is a search with a policy bolted on. Longest-line BFS gives you levels and shortest
paths; DFS with timing marks gives you components, cycles, and topological orders; both give every
later algorithm its first visit to a node. Nail the "_mark on discovery, then the queue/stack
decides the tale_" habit now and the harder graph days become variations, not rediscoveries.

Solve the two problems above. In Course Schedule, watch Kahn's queue alone decide acyclicity; in
Clone Graph, watch the visited map decide the shape of the copy.
