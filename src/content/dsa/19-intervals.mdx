## The one question this page answers

Intervals are time with beginning and end — and the trap is that each interval can relate to every
other one, begging an O(n²) comparison. The page answers one question: _is there an ordering that
makes comparisons local?_ Sorting by start gives the yes: with every later start at or after the one
in hand, a single sweep window captures all the overlap that matters, and merging takes one pass.

## Start with an analogy

A wall of sticky notes, each a colored stripe with a start tick and an end tick. To merge them you
do not hold the whole wall in your head: line the notes up left to right by their left edge, then
slide a single ruler across. Whenever the next note starts while the ruler is still over the current
stripe, extend the ruler to cover both ends. When the next note starts past the ruler’s edge, the
stripe is complete — pin it to the board and start a new one.

The ruler is the **current window**; lining up is **sorting by start**; sliding across is **the
sweep**.

## Overlap, decoded

For two intervals where the second starts at or after the first — which sorting guarantees — the
whole relationship is one comparison: `next.start ≤ current.end`. When it holds, they overlap (or
touch) and merge into `[current.start, max(current.end, next.end)]`. When
`next.start > current.end`, there is a genuine gap and no merge. Containment falls out of the same
rule: an interval inside the window still satisfies the test, and `max` simply keeps the window
unchanged.

## Merging in one pass

With sorting in hand, the algorithm is a straight left-to-right fold:

1. Sort the intervals by start time.
2. Open a window on the first interval.
3. For each next interval: if `next.start ≤ window.end`, extend `window.end` to the larger of the
   two ends; otherwise push the finished window into the result and open a new one on `next`.
4. Push the last window.

Cost: O(n log n) for the sort, then O(n) for a sweep that touches each interval a constant number of
times. Every merge problem settles on the same spine; only the "what to print at each event"
changes.

## Meeting Rooms: the same sweep, a yes/no answer

Meeting Rooms asks whether a single person could attend every meeting — whether any two intervals
overlap. Same skeleton:

1. Sort by start.
2. For each consecutive pair, if `next.start < current.end`, a meeting begins while an earlier one
   is still running — return false.

The strict `<` encodes the boundary rule: a meeting ending exactly when the next starts uses no
shared time, so equal endpoints are legal. Everything else — "does a room exist", "fewest rooms",
"how many overlaps at the busiest minute" — is the same sort-and-sweep wearing different hats.

## What this is NOT

| Misconception                               | Truth                                                                                                    |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| "Interval problems need pairwise checks"    | Sorting makes one sweep window sufficient; pairwise comparison is redundant O(n²) legwork.               |
| "Touching ends count as overlap"            | [a, b] then [b, c] are mergeable into [a, c], and a person can attend both meeting rooms back to back.   |
| "A contained interval shrinks the window"   | A merge only ever extends or keeps; the max end is the only number that moves.                           |
| "The sweep itself makes the algorithm fast" | The linear sweep is the dessert; the O(n log n) sort is the meal that makes the victory possible.        |
| "Meeting Rooms and Merge Intervals differ"  | They are one algorithm: same sort, same consecutive comparison, different output (bool vs merged array). |

## Why this matters for the rest of the trip

Intervals are the shape of time, and time-shaped problems — calendar overlap, meeting rooms, load in
a CPU scheduler, coverage — nearly all reduce to sort + sweep. The habit of _ordering the data until
comparisons become local_ is the same instinct the greedy day sharpened and the same pre-step binary
search demands: make the world monotone, then one glance answers the question. Master the ascending
start and the single window, and the interval family stops being a list of puzzles.

Solve the two problems above. Merge Intervals is the fold; Meeting Rooms is the same fold asked as a
question — make sure you can state when the two stop being the same program.
